# CroLingo review, 2026-08-09

A snapshot of technical debt and oddities found while working through the
repository on 2026-08-09, at commit `8f993bf` (`0.0.55+56`). Every entry was
verified against the tree rather than inferred, and each states what is
actually wrong, not merely what looks unusual.

Severity is about consequence, not effort:

| Severity | Meaning |
| --- | --- |
| **High** | Can break a release, lose data, or block an upgrade path |
| **Medium** | Will cost real time or force a rushed decision later |
| **Low** | Worth knowing; safe to leave for now |
| **Accepted** | Deliberate, documented, and correct for today |

## 0. `sqlite3_flutter_libs` is marked end-of-life — High

`pubspec.lock:863` pins `sqlite3_flutter_libs` 0.5.42 while pub reports
`0.6.0+eol` available. The `+eol` suffix is the maintainer declaring the
package finished. It sits under `drift_flutter` in the persistence path, so
every learner's progress database depends on it.

Nothing is broken today, but an abandoned native dependency on the storage
path is the kind of thing that becomes urgent on someone else's schedule —
an Android NDK or Gradle change, not ours. Investigate what drift recommends
instead before it is forced.

## 1. `drift_flutter` is held back by our own constraint — Medium

`pubspec.yaml:34` declares `drift_flutter: ^0.2.8`. For a pre-1.0 package a
caret stops below `0.3.0`, so 0.3.1 is unreachable without an explicit edit.
This is almost certainly the same thread as entry 0 and should be looked at
with it, not separately.

## 2. Deprecated Android Gradle flags — Medium

`android/gradle.properties:4` and `:6` set `android.newDsl=false` and
`android.builtInKotlin=false`. Both carry Flutter template comments, both are
deprecated by AGP 9, and AGP 10 removes them.

The trap is that they are global: they also govern `audioplayers_android`,
`jni`, `jni_flutter` and `sqlite3_flutter_libs`, which we do not control. The
sensible trigger is Flutter dropping them from its template, not a local
experiment. Until then the pipeline's warning review names them so they are
not mistaken for something new.

## 3. Dependabot can never merge here — Medium

Every commit must bump `pubspec.yaml`, and Dependabot does not know that, so
`tool/check_version.dart` fails its branch. Pull request #2 was red on that
stage alone; every other gate passed.

The bump was applied by hand instead (`8f993bf`), which is correct but does
not scale: each future Dependabot pull request needs the same manual
treatment. Either accept that recurring cost or give the version gate a
narrow, documented exemption for changes touching only
`.github/workflows/**`. Choose deliberately rather than by attrition.

## 4. Two agents share one working tree — Medium

Not a code defect, but it cost more time today than any bug. Two agents
committing into the same checkout means two full pipelines competing for
`build/`, `.dart_tool/` and the Gradle daemon; one run was killed mid-build
that way, and the shared `pubspec.yaml` version counter forced repeated
re-bumps.

`docs/AGENTS.md` now tells agents to stage only files they own and to wait
for overlapping work. That helps with correctness, not with contention. If
parallel agents continue, give each a separate worktree with its own build
directory.

## 5. Drift returns local-flavoured timestamps — Low

The repository rule is UTC in storage, local only at the boundary, and
`DriftProgressRepository` honours it. But drift hands back `DateTime` values
in local flavour, so a stored `DateTime.utc(...)` returns as the same instant
with a different offset. `test/data/progress/app_database_test.dart` therefore
compares instants with `isAtSameMomentAs`.

Correct today because every consumer treats the value as an instant. It would
become a real bug the moment someone compares one of these to a `DateTime.utc`
with `==`, or formats one without converting.

## 6. `lesson_screen.dart` is still the largest screen — Low

406 lines at `lib/features/lesson/lesson_screen.dart`, against 304 for the
next largest. The four exercise families were extracted into
`lib/features/lesson/widgets/` (`5520c8c`), so what remains is genuine
orchestration: session state, the answer lifecycle, and routing between
families. Worth watching rather than splitting again for its own sake.

## 7. Five lines cannot be covered from a headless test — Low

`lib/data/audio/asset_feedback_audio_service.dart:17`, `:19`, `:20` construct
and drive the real `audioplayers` plugin, and
`lib/data/speech/platform_speech_service.dart:102`, `:105` branch on the host
platform. Neither can run under `flutter test`.

Coverage is 98.29% against a 98% floor, so these cost roughly a third of the
remaining headroom. Testing them needs an integration target, which does not
exist yet.

## 8. The database provider is untested — Low

`lib/app/providers.dart:21`–`:23` opens the production database via
`driftDatabase(name:)`, which needs `path_provider` and therefore a real
platform. `test/app/providers_test.dart` overrides it, so the wiring around it
is proven but its own three lines are not.

## 9. Two small error branches remain untested — Low

`lib/features/profile/profile_screen.dart:52` renders the "statistics could
not be loaded" state, and `lib/app/router.dart:26` is the settings-loading
fallback on the lesson route. Both resisted a clean test — a `pumpAndSettle`
that never settles because an indicator keeps animating — and both are
one-line fallbacks. Left untested deliberately rather than propped up with a
test that asserts framework behaviour.

## 10. The product specification is excluded from linting — Low

`.markdownlint-cli2.yaml` ignores `docs/00_product_spec.md`. It is the largest
document in the repository and the only unlinted one, so formatting drift
there is invisible. Presumably deliberate given its size; worth confirming it
is a decision and not an accident.

## 11. The app bundles its own `pubspec.yaml` — Accepted

`AppVersion` reads the bundled manifest so the dashboard can show the running
version from the single source of truth. Bundling a build manifest into a
shipped app is unusual, and it does place dependency names inside the package.

The alternative — generating a Dart constant — would create a second source
that drifts the first time someone forgets to regenerate it, and this
repository bumps the version in *every* commit. The manifest is already public
in a public repository, so the trade is worth it. Revisit only if the pubspec
ever holds something private, which it must not.

## 12. The warning review never fails the build — Accepted

`localPipeline.sh` classifies upstream warnings and lists anything it cannot
account for, but always exits zero. That is deliberate: failing on an upstream
rewording would train people to ignore the stage. The cost is that a genuinely
new warning is only *reported*, so it needs a human to read the summary.

## 13. Coverage ignores the Drift table declarations — Accepted

`lib/data/progress/app_database.dart` wraps its table classes in
`coverage:ignore`. Their column getters are read by the code generator and
never execute at runtime, so no test can reach them; leaving 21 unreachable
lines in the denominator would have meant either a fake test or a permanently
depressed number. `docs/AGENTS.md` records that this marker is only ever for
declaration-only code.

## Fixed on 2026-08-09

Recorded so they are not rediscovered as open problems:

- **The pipeline hid its own failures.** A missing tool made every later stage
  fail with `command not found`, then the run crashed before printing a
  summary and deleted its own logs. It now restores tooling via
  `scripts/bootstrap.sh`, stops early when it cannot, and keeps logs on
  failure (`ba6af8a`).
- **The correct-answer green was inaccessible.** `#2DAA63` gave 2.67:1 against
  its feedback surface, under the 3:1 floor for a non-text icon. Now `#187A43`
  (`b643f11`).
- **The dashboard stat cards overflowed by 37 pixels** at a real phone width;
  the repository requires overflow-free layout to 320 pixels (`233c0b4`).
- **The mascot would have kept the old palette** after a theme change, because
  its painter declared `shouldRepaint => false` (`b643f11`).
- **`learning_path_screen.dart` had no test**; an untracked test directory had
  been destroyed by `git clean -xfd` and the gap was invisible in the diff
  (`9e11ec8`).
